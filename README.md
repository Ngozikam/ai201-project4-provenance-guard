# ai201-project4-provenance-guard
AI-powered content provenance detection system using multi-signal classification, confidence scoring, transparency labels, audit logging, and creator appeals built with Flask and Groq API.


# Milestone 6 – Documentation and Project Walkthrough

## Project Overview

Provenance Guard is a multi-signal AI content attribution system developed using Flask. The system estimates whether submitted text is likely written by a human or generated by artificial intelligence by combining two independent detection signals:

1. A Large Language Model (LLM)-based detector using the Groq API.
2. A stylometric analyzer based on writing characteristics.

The outputs of both detectors are combined into a weighted confidence score, which determines the final attribution and transparency label. Every submission is recorded in a structured audit log, creators can submit appeals, and rate limiting is enforced to prevent API abuse.

# Detection Signals

## Signal 1 – Groq LLM Classifier

The first detection signal uses a Large Language Model through the Groq API. The model analyzes the submitted text and estimates whether it resembles AI-generated or human-written content.

### Why this signal?

Large language models recognize patterns commonly found in AI-generated text, including sentence structure, wording, and overall writing style.

### Strengths

- Good at identifying typical AI-generated writing.
- Produces an interpretable confidence score.

### Limitations

- Can occasionally classify polished human writing as AI-generated.
- Depends on the external LLM model.

---

## Signal 2 – Stylometric Analysis

The second detection signal analyzes measurable writing characteristics.

Metrics include:

- Average sentence length
- Sentence length variance
- Type-token ratio
- Punctuation density

These features are combined into a stylometric score.

### Why this signal?

Stylometric analysis is independent of the LLM and provides an additional source of evidence.

### Strengths

- Fast
- Fully local
- Explainable

### Limitations

- Very short passages provide little stylometric information.
- Professional writers and AI systems can sometimes produce similar writing statistics.

---

# Confidence Scoring

The final confidence score combines both detection signals.

```
Confidence =
0.70 × LLM Score
+
0.30 × Stylometric Score
```

The LLM score receives greater weight because it provides stronger semantic evidence, while stylometric analysis serves as an independent supporting signal.

The combined confidence is interpreted as follows:

| Confidence  | Attribution  |
|-------------|--------------|
| ≥ 0.85      | Likely AI    |
| 0.60 – 0.84 | Uncertain    |
| ≤ 0.59      | Likely Human |

# Transparency Labels

The system returns one of three transparency labels.

## Likely AI

> Likely AI-Generated: This content appears likely to have been generated using artificial intelligence. Confidence: High. This assessment was produced automatically and may not always be correct.

---

## Likely Human

> Likely Human-Written: This content appears likely to have been written by a human author. Confidence: High. This assessment was produced automatically and may not always be correct.

---

## Uncertain

> Uncertain Attribution: The system could not confidently determine whether this content was written by a human or generated using artificial intelligence. Confidence: Moderate. Additional review may be required.

# Known Limitations

One limitation of the system is that highly edited AI-generated content may appear similar to professional human writing. Such content can produce human-like stylometric features while still receiving moderate LLM scores, resulting in an "Uncertain" classification.

Similarly, very short text submissions contain insufficient stylometric information, reducing the effectiveness of the second detection signal.

# Project Walkthrough 

## 1. Project Introduction


Provenance Guard is a multi-signal AI content attribution system developed using the Flask web framework. The purpose of the system is to estimate whether submitted text is likely written by a human or generated by artificial intelligence by combining evidence from multiple independent detection signals.

The system integrates two complementary analysis methods: a **Groq Large Language Model (LLM) classifier**, which evaluates the semantic characteristics of the text, and a **stylometric analyzer**, which examines measurable writing features such as sentence structure, vocabulary diversity, and punctuation patterns. The outputs of these two detection signals are combined using a weighted confidence scoring algorithm to produce a final attribution result.

To improve transparency and accountability, the system generates descriptive transparency labels, records every submission and appeal in a structured audit log, supports a creator appeal workflow for disputed classifications, and protects the API against excessive requests through rate limiting. Together, these components provide a complete end-to-end AI content attribution pipeline that emphasizes explainability, traceability, and responsible use of AI-assisted content analysis.

---

## 2. Architecture Overview

The Provenance Guard system follows a multi-stage processing pipeline that combines multiple detection signals to improve the reliability and transparency of AI content attribution. A user submits text through the `/submit` endpoint, where the request is received and processed by the Flask API. The submitted text is simultaneously analyzed by two independent detection components: the **Groq LLM classifier**, which evaluates semantic characteristics and produces an LLM score, and the **stylometric analyzer**, which evaluates writing style characteristics and produces a stylometric score.

The outputs from both detection signals are forwarded to the **confidence scorer**, which combines the two scores using a weighted confidence model consisting of **70% LLM score** and **30% stylometric score**. Based on the computed confidence value, the system determines the final attribution result (**Likely Human**, **Uncertain**, or **Likely AI**) and generates an appropriate transparency label describing the confidence of the automated decision.

To ensure transparency, accountability, and traceability, every classification result is recorded in a structured audit log (`logs/audit_log.json`). The API then returns a JSON response containing the content identifier, attribution result, confidence score, transparency label, and the individual scores from both detection signals.

## 3. Text Submission

The `/submit` endpoint is used to analyze a text sample and estimate whether it is likely human-written or AI-generated. The client submits the text along with a unique creator identifier. The system processes the text using the Groq LLM classifier and the stylometric analyzer, combines both detection signals into a weighted confidence score, and returns the final attribution result.

### Request

**Endpoint**

```
POST /submit
```

**Input**

```json
{
    "text": "The sun dipped below the horizon, painting the sky in hues of amber and rose. I sat on the porch, coffee in hand, watching the neighborhood slowly go quiet.",
    "creator_id": "appeal-test"
}
```

### Response

```json
{
    "content_id": "cf55d916-9bf4-4502-a1cf-557c08a51e4b",
    "creator_id": "appeal-test",
    "attribution": "likely_human",
    "confidence": 0.33,
    "label": "This content appears likely to have been written by a human author. This assessment was produced automatically and may not always be correct.",
    "llm_score": 0.20,
    "stylometric_score": 0.63
}
```

### Explanation

The response includes:

- **content_id:** A unique identifier assigned to the submitted content.
- **creator_id:** The identifier of the user who submitted the text.
- **attribution:** The final classification (`likely_human`, `uncertain`, or `likely_ai`).
- **confidence:** The weighted confidence score computed from both detection signals.
- **label:** A transparency message explaining the attribution result.
- **llm_score:** The score produced by the Groq LLM classifier.
- **stylometric_score:** The score produced by the stylometric analyzer.

This demonstrates the complete end-to-end analysis pipeline, where two independent detection signals are combined to produce an interpretable AI attribution result.

## 4. Appeal Workflow


The `/appeal` endpoint allows a content creator to request a manual review if they disagree with the automated attribution result. The creator submits the unique content identifier together with a brief explanation describing why they believe the classification should be reconsidered. The system records the appeal in the audit log, updates the submission status to **under_review**, and returns a confirmation message.

### Request

**Endpoint**

```
POST /appeal
```

**Input**

```json
{
    "content_id": "cf55d916-9bf4-4502-a1cf-557c08a51e4b",
    "creator_reasoning": "I wrote this content myself from personal experience."
}
```

### Response

```json
{
    "content_id": "cf55d916-9bf4-4502-a1cf-557c08a51e4b",
    "status": "under_review",
    "message": "Appeal received and logged for review."
}
```

### Explanation

The response includes:

- **content_id:** The unique identifier of the content being appealed.
- **status:** Indicates that the appeal has been received and is awaiting manual review.
- **message:** Confirms that the appeal has been successfully recorded.

In addition to returning this response, the system creates a new audit log entry containing the appeal details, including the content ID, timestamp, creator's reasoning, event type, and review status. This ensures that every appeal is fully traceable and preserved for future review.

The `/log` endpoint retrieves the complete audit history of the Provenance Guard system. It returns all recorded submissions and appeals in chronological order, allowing users or administrators to trace every classification decision and any subsequent appeal.

```
GET /log
```

**Input**

No input parameters are required.

### Response

```json
{
    "entries": [
        {
            "content_id": "cf55d916-9bf4-4502-a1cf-557c08a51e4b",
            "creator_id": "appeal-test",
            "timestamp": "2026-07-04T06:46:14.926940Z",

            "timestamp": "2026-07-04T06:55:58.676041Z",
            "status": "under_review",
            "appeal_reasoning": "I wrote this content myself from personal experience.",
            "event_type": "appeal"
        }
    ]

```

### Explanation

The audit log contains a complete history of every submission and appeal. Each classification entry records:

- **content_id:** Unique identifier of the submitted content.
- **creator_id:** Identifier of the content creator.
- **timestamp:** Date and time when the submission was processed.
- **attribution:** Final classification result.
- **confidence:** Combined confidence score.
- **llm_score:** Score generated by the Groq LLM classifier.
- **stylometric_score:** Score generated by the stylometric analyzer.
- **status:** Current classification status.

Each appeal entry records:

- **content_id:** Identifier of the appealed content.
- **timestamp:** Date and time when the appeal was submitted.
- **appeal_reasoning:** Explanation provided by the creator.
- **event_type:** Indicates that the entry is an appeal.
- **status:** Current appeal status (`under_review`).

This structured audit log provides complete traceability for every classification and appeal, ensuring transparency and accountability throughout the AI content attribution process.

## 6. Rate Limiting

To improve the security and reliability of the API, the `/submit` endpoint is protected using **Flask-Limiter**. Rate limiting helps prevent excessive requests, accidental misuse, and automated abuse by restricting how frequently a client can access the endpoint.

### Configuration

The `/submit` endpoint is configured with the following limits:

- **10 requests per minute**
- **100 requests per day**

These limits are enforced automatically for each client.

### Expected Behavior

When a client submits requests within the configured limits, the API processes the request normally and returns an **HTTP 200 (OK)** response.

When the request limit is exceeded, Flask-Limiter blocks the request and returns an **HTTP 429 (Too Many Requests)** response.

### Example Test Results

```text

200
200
429
429
```

The first requests were processed successfully, while the remaining requests exceeded the configured limit and were rejected with an HTTP **429 (Too Many Requests)** response.

### Explanation

The rate-limiting mechanism protects the Provenance Guard API from denial-of-service attacks, automated bots, and excessive client requests. It also helps ensure fair usage by preventing a single client from consuming excessive server resources while maintaining reliable service for all users.

The system integrates a Groq LLM classifier and a stylometric analyzer to independently evaluate submitted text.
